# Architecture

```
formskills/
├── core/            formskills-core: the list (core/data/apps.json, compiled in), catalogue, fetch, index, library
├── cli/             formskills-cli: apps, app, skills, fetch, search, check, read, download, edits, edit, catalog, where, version
├── src-tauri/       the shell: the window
├── frontend/        the window: tokens, layers, chips, cards, the detail pane
├── setup/apps.py    core/data/apps.json from formcompiler's registry
└── assets/          the owner's icon
```

## One engine, thin surfaces

`formskills-core` owns everything that matters: today the list, from v0.2.0 reading the catalogue, fetching and checking each app's released skills asset and keeping it in a local cache, and from v0.4.0 the personal edited copies. `formskills-cli` and the shell call it and add nothing.

## The list

`core/data/apps.json` (format `formskills-apps`, version 2) is generated by `setup/apps.py` from formcompiler's registry: for every app whose `agents.skills` names a folder, its catalogue id, name, kind, topic (from the kind, through `TOPICS` in the script, which fails on a kind it has no topic for), licence and summary, its repository, that folder, its release state and whether it is released at all. It records formcompiler's version and commit. It is compiled into the engine with `include_str!` and imported by the window at build time, so both read the same bytes and nothing is fetched.

## Where the skills come from (v0.2.0)

formcompiler attaches `<app>-skills-vX.Y.Z.zip` to every release, built from the app's skills folder, and the signed family catalogue carries its address and digest (`channels.stable.agents.skills`). formskills reads only that: what it shows is exactly what shipped.

- `catalog.rs` reads and checks the catalogue with FormPortal's trust model and keys (FormPortal's kept copy when offline).
- `fetch.rs` downloads an asset only when the kept one has another digest, checks its SHA-256, unpacks it safely into a hidden folder and moves it into `released/<app>/<version>/`, then removes the app's older versions. When the network or catalogue fails, the newest kept version is used and the reason shown.
- `skills.rs` indexes a skills folder the way formcompiler builds it: each folder with a `SKILL.md`, its name and description, and its files marked as skill, sub-skill, reference or file.
- `library.rs` gives every app one source (`release`, `kept`, `dev` or `missing`) and its skills. Dev mode, off by default, reads checkouts instead.

The shell's `library` and `refresh` commands return that, off the main thread.

## Your copies (v0.4.0)

`edits.rs` keeps each copy in `edits/<app>/<skill>/` with `<skill>.edit.json` beside it: the base it was copied from and a SHA-256 of each original file. From those it reports which files you changed and which files the original changed since (the "original updated" flag); Mark as seen records the original's current digests. Writes replace one existing file of the copy, beside and renamed. Nothing writes to `released/` or to a checkout. The shell's `edit_*` commands pass app ids, skill folders and paths only.

## Search and the format check (v0.5.0)

`search.rs` reads the Markdown files of every skill in the library (each up to 2 MB, front matter left out) and keeps the skills holding every word of the query at the start of a word; a word in the name or folder counts 8, in the description 4, and each place in the text 1 (at most 5 per word). The 60 best come back with the first line that matched. `check.rs` checks a skill folder against the Agent Skills format (agentskills.io/specification) and Claude's rules for names and descriptions: errors for a missing or unclosed front matter, a missing, long or badly formed name, a name that differs from the folder or holds XML tags or a reserved word, a missing or long description or one with XML tags, and a compatibility outside 1 to 500 characters; notes for a `SKILL.md` over 500 lines and links (outside code) that leave the skill or miss a file. The index stores each skill's licence and its check summary; the shell's `search`, `check_skill` and `edit_check` pass ids and words only.

## Reading and downloading (v0.3.0)

The shell keeps the last library, with each app's skills folder, and never sends a folder to the page. `read_file` takes an app id and a path in the set; `library::read_text` refuses anything that is not plain path parts or that resolves outside the folder, and returns text or a note. `download` packs one skill or the set with `pack.rs`, shaped like formcompiler's asset, into the Downloads folder without replacing a file. The page renders Markdown with `markdown.ts` (the family's renderer), which builds DOM nodes and never parses HTML.

## The window

The page is built once from the list. The body stays hidden (`html.booting`) until `main.ts` has created every chip and card and filled the count, then the class is removed: the first frame is the final layout, on the theme's ground colour, with no flash. Chips toggle `hidden` on existing cards; choosing a card fills fixed slots in the detail pane, whose size is set by the layout, so nothing outside it moves. The chip row scrolls sideways at a fixed height rather than wrapping. Every `z-index` comes from `layers.css` and every colour, space and radius from `tokens.css` (the Form family tokens, with the orange and violet accents of the icon).
